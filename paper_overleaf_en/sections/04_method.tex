\subsection{First-Stage Retrieval}

The first stage retrieves a high-recall candidate pool before any knowledge-aware reranking is applied. We employ BM25 as the lexical baseline, dense retrieval as the semantic baseline, and Reciprocal Rank Fusion (RRF) as the default hybrid retriever. For a retrieval source $s$, let $r_s(q,d)$ be the rank of passage $d$ for question $q$. The fused score is:
\[
  \mathrm{RRF}(q,d)=\sum_{s \in S}\frac{w_s}{k+r_s(q,d)},
\]
where $S$ is the set of retrieval sources, $w_s$ is a source weight, and $k=60$ in the reported experiments. The original Hybrid RRF uses BM25 and dense retrieval with equal weights.

The enhanced candidate-generation path is designed to raise the top-100 ceiling for reranking. It adds fielded BM25 with title, text, and MeSH expansion fields, plus MedCPT dual-encoder dense retrieval as an additional biomedical semantic source. Fusion weights are selected on the validation split only. The selected w122 configuration gives BM25 and dense retrieval weight 1.0, fielded BM25 weight 1.2, and MedCPT dual-encoder retrieval weight 0.2. This setting is selected for validation Recall@100 rather than test performance, because reranking can improve only passages already present in the candidate pool.

\subsection{Knowledge-Constrained Local Structure}

For each question and its top-$M$ candidates, KCH-MedRank builds feature variants with increasing structural assumptions. The flat knowledge variant uses retrieval, biomedical semantic, MeSH, entity, and relation features without any graph construction. The pairwise graph variant adds anchor-based edges among the same local objects. The hypergraph variant builds a local hypergraph $H_q=(V_q,\mathcal{E}_q)$ whose node set includes a question node, candidate passage nodes, document nodes, biomedical entity nodes, MeSH concept nodes, optional MeSH tree nodes, and optional relation nodes. The hyperedge set connects multiple nodes at once and therefore represents higher-order relations not naturally captured by pairwise similarity alone.

The main hyperedge types are question-entity, question-MeSH, question-passage candidate, passage-entity, passage-document, document-MeSH, shared-entity passages, entity-type concept, MeSH hierarchy, and auxiliary PrimeKG relation edges. Pairwise graph and no-medical-knowledge variants are constructed from the same candidate pool for ablation: the pairwise variant decomposes multi-node hyperedges into anchor-based pairwise edges, while the no-knowledge variant keeps only rank-band and candidate structure.

The local design avoids constructing a global graph over millions of biomedical passages. It also keeps the method interpretable: feature inspection and case studies can report which concept overlaps, hierarchy links, shared candidate clusters, or graph and hypergraph centrality signals influenced reranking.

\subsection{Hypergraph Diffusion and Structural Features}

KCH-MedRank employs hypergraph diffusion as an interpretable feature rather than as a standalone ranking formula. The seed distribution places mass on the question node, question entity nodes, and question MeSH nodes. At each iteration, scores are propagated through weighted hyperedges:
\[
  x^{(t+1)}=(1-\alpha)x^{(0)}+\alpha \cdot \mathrm{Propagate}(x^{(t)},\mathcal{E}_q),
\]
where $\alpha=0.85$ and the implementation uses three diffusion iterations. Passage-level diffusion scores are then min-max normalized within each question candidate set. We also compute weighted degree centrality, local node and hyperedge counts, shared-entity edge counts, document-MeSH edge counts, and optional hierarchy-edge counts.

\subsection{Biomedical Knowledge Features}

The reranker draws on three complementary medical knowledge dimensions. \textbf{Entity features} measure concept-level alignment between questions and passages: entity overlap count, Jaccard similarity, question entity coverage, and passage entity count. \textbf{MeSH features} span two granularities. Exact MeSH features capture direct descriptor overlap: MeSH overlap count, Jaccard similarity, question MeSH coverage, and passage MeSH count. Hierarchy-aware MeSH features exploit the tree structure: exact descriptor overlap, parent match, ancestor match, sibling match, tree-distance similarity, query concept coverage, passage hierarchy coverage, passage concept specificity, and shared candidate clusters over MeSH terms or parent concepts. \textbf{PrimeKG relation features} provide auxiliary relational signals (relation count, question relation coverage, local relation-edge count) but are down-weighted due to sparse exact-name coverage.

\subsection{Learning-to-Rank}

The supervised reranker is a query-group LambdaMART model trained with LightGBM~\citep{ke2017lightgbm}. Each question defines one ranking group; candidate passages within that group form the rows; and binary relevance labels are derived from gold evidence annotations. The feature vector concatenates retrieval scores and ranks, the precomputed biomedical semantic score, entity features, exact and hierarchy-aware MeSH features, auxiliary relation features, and---for structural variants---diffusion scores, centrality measures, and local graph-count features.

Hyperparameters are tuned on the validation split over number of leaves $\{15,31\}$, learning rate $\{0.03,0.05\}$, number of estimators $\{80,160\}$, and a blend weight $\{0,0.1,0.2,0.35\}$ that interpolates between the model score and the original candidate rank. Selection uses validation MRR@10 as the primary metric, with Recall@10 and nDCG@10 as secondary criteria. The final model is trained on the combined train-plus-validation set and evaluated exactly once on the held-out test split.
