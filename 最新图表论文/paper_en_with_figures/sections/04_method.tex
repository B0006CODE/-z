\subsection{Overall Framework}

\input{figures/method_overview_en}

KCH-MedRank builds a final evidence ranking in four connected stages: multi-source candidate retrieval, flat biomedical knowledge feature extraction, optional local hypergraph construction with diffusion-based structural features, and query-group LambdaMART learning-to-rank. The framework is designed so that each component can be ablated independently. Removing the hypergraph yields the flat knowledge baseline. Stripping MeSH and entity annotations from the hypergraph yields the no-knowledge variant. Breaking multi-node hyperedges into anchor-based pairwise edges produces the graph decomposition baseline.

\subsubsection{First-Stage Candidate Generation}

The reranker can only reorder passages already in the candidate pool, so the first-stage ceiling matters. We use four retrieval sources: BM25 as the lexical baseline~\citep{robertson2009bm25}, dense biomedical retrieval as the semantic baseline, fielded BM25 with title, text, and MeSH expansion fields, and MedCPT dual-encoder retrieval~\citep{jin2023medcpt} as an additional biomedical semantic source. These are fused via weighted Reciprocal Rank Fusion~\citep{cormack2009rrf}:

\[
  \mathrm{RRF}(q,d)=\sum_{s \in S}\frac{w_s}{k+r_s(q,d)},
\]

where $r_s(q,d)$ is the rank of passage $d$ under source $s$, $w_s$ is the source weight, and $k=60$. The selected w122 configuration uses BM25 and dense retrieval at weight 1.0, fielded BM25 at 1.2, and MedCPT dual-encoder at 0.2. This setting is chosen solely to maximize validation Recall@100, never test performance, because reranking can only improve passages that the first stage places in the candidate pool.

\subsubsection{Flat Biomedical Knowledge Features}

The core of KCH-MedRank is the set of biomedical knowledge features computed for each query-passage pair without any graph construction. These features encode what a clinician would check when comparing a question to a candidate passage: shared concepts, hierarchical relationships, and known biomedical relations.

Entity features measure concept-level alignment. Let $E_q$ and $E_d$ be the sets of biomedical entities extracted from $q$ and $d$:
\[
  \phi_{\text{ent--jacc}} = \frac{|E_q \cap E_d|}{|E_q \cup E_d|}, \quad
  \phi_{\text{ent--cov}} = \frac{|E_q \cap E_d|}{|E_q|}.
\]

MeSH features operate at two granularities. Let $M_q$ and $M_d$ be the sets of MeSH descriptor identifiers. Exact MeSH features capture direct descriptor overlap:
\[
  \phi_{\text{mesh--jacc}} = \frac{|M_q \cap M_d|}{|M_q \cup M_d|}, \quad
  \phi_{\text{mesh--cov}} = \frac{|M_q \cap M_d|}{|M_q|}.
\]

Hierarchy-aware MeSH features exploit the tree structure. Every MeSH concept carries ancestor, parent, sibling, and descendant relationships. Let $T(m)$ denote the ancestor set of concept $m$ and $d_T(m_1, m_2)$ the shortest-path distance in the MeSH tree:
\[
  \phi_{\text{tree--sim}} = \frac{1}{|M_q|}\sum_{m \in M_q} \max_{m' \in M_d} \frac{1}{1 + d_T(m, m')}, \quad
  \phi_{\text{anc--match}} = |T(M_q) \cap M_d|.
\]

Additional hierarchy features include parent match, sibling match, passage hierarchy coverage, passage concept specificity, and shared candidate clusters over MeSH terms or parent concepts.

PrimeKG relation features supply auxiliary relational signals. Let $R_q$ and $R_d$ denote relation identifier sets:
\[
  \phi_{\text{rel--cnt}} = |R_q \cap R_d|, \quad
  \phi_{\text{rel--cov}} = \frac{|R_q \cap R_d|}{|R_q|}.
\]

These are down-weighted in the final model. Exact-name coverage in PrimeKG is sparse; only a fraction of biomedical entities have exact-name matches in the knowledge graph.

\paragraph{Synonym-Aware Feature Augmentation.}
Exact entity and MeSH matching is brittle against biomedical synonyms and abbreviations. A question asking about ``DITPA'' and a gold passage describing ``3,5-diiodothyropropionic acid'' share the same clinical concept but register zero overlap under exact-name matching. We introduce a lightweight normalization module that bridges this gap through text-level variant expansion without requiring full UMLS concept linking.

For each biomedical entity encountered in a question or passage, we build a variant set $\mathcal{V}(e)$ containing (i) the canonical entity name, (ii) all surface forms observed during entity dictionary construction, and (iii) MeSH descriptor entry terms from the NLM 2026 MeSH release mapped through shared normalized forms. The MeSH synonym resource provides 213,754 entry terms across 31,110 descriptors~\citep{nlm2026mesh}. For a MeSH descriptor with identifier $m$, its variant set includes all entry terms and the normalized descriptor name.

Normalization applies four text-level operations: Greek character ASCII conversion (e.g., $\alpha \rightarrow$ alpha), whitespace normalization, hyphen-space flattening, and lightweight deterministic stemming for plural forms (e.g., ``ubiquitinated proteins'' $\rightarrow$ ``ubiquitinated protein''). These operations are purely rule-based and add no inference cost at reranking time.

We compute four classes of synonym-aware features for each query-passage pair:

\begin{enumerate}[leftmargin=*,nosep]
    \item \textbf{Normalized entity variant overlap:} $\phi_{\text{norm-ent-overlap}} = |\mathcal{V}(E_q) \cap \mathcal{V}(E_d)|$, $\phi_{\text{norm-ent-jacc}} = \frac{|\mathcal{V}(E_q) \cap \mathcal{V}(E_d)|}{|\mathcal{V}(E_q) \cup \mathcal{V}(E_d)|}$, and $\phi_{\text{norm-ent-cov}} = \frac{|\mathcal{V}(E_q) \cap \mathcal{V}(E_d)|}{|\mathcal{V}(E_q)|}$.
    \item \textbf{Cross-text MeSH alias overlap:} the count of passage MeSH entry terms that appear verbatim in the question text, $\phi_{\text{q2pm-alias}} = |\{t \in \mathcal{V}(M_d) : t \text{ contained in } q\}|$, and the reverse direction $\phi_{\text{p2qm-alias}}$.
    \item \textbf{Abbreviation bridging:} short-form/long-form abbreviation pairs are extracted from the question text via a regular-expression pattern (e.g., ``cGAS (cyclic GMP-AMP synthase)''). The matched abbreviation set $\mathcal{A}(q)$ is compared against the passage text: $\phi_{\text{abbr-match}} = |\{a \in \mathcal{A}(q) : a \text{ contained in } d\}|$.
    \item \textbf{Query-primary / passage-major MeSH overlap:} the count of shared MeSH descriptors where the question side uses the query primary MeSH (top-ranked automatic match) and the passage side uses NLM-indexed major topics (starred MeSH), $\phi_{\text{mesh-major}} = |M_q^{\text{primary}} \cap M_d^{\text{major}}|$, with a weighted composite $\phi_{\text{mesh-weighted}}$ that linearly combines normalized MeSH overlap, primary/major overlap, and cross-text alias counts.
\end{enumerate}

These features add 16 dimensions to the feature vector $\boldsymbol{\phi}(q,d)$. The important design choice is that the module does not perform entity linking or UMLS concept normalization. It expands the matching surface through known synonym sets without altering the entity resolution pipeline. This keeps the module lightweight while addressing the most frequent failure patterns identified in our error analysis.

\subsubsection{Knowledge-Constrained Local Hypergraph}

For each question and its top-$M$ candidates we optionally build a local hypergraph $H_q=(V_q,\mathcal{E}_q)$. The node set carries a question node, candidate passage nodes, document nodes, biomedical entity nodes, MeSH concept nodes, optional MeSH tree nodes, and optional relation nodes. Hyperedge connections span multiple nodes at once and capture higher-order relations that pairwise graphs fragment.

The hyperedge types are question-entity, question-MeSH, question-passage candidate, passage-entity, passage-document, document-MeSH, shared-entity passages, entity-type concept, MeSH hierarchy, and auxiliary PrimeKG relation edges. Each hyperedge carries a weight reflecting evidence strength. For entity-set overlap:
\[
  w_{\text{ent}}(q,d) = \frac{|E_q \cap E_d|}{|E_q|}.
\]
For MeSH hierarchy edges linking concept $m$ to its parent $p$:
\[
  w_{\text{hier}}(m,p) = \frac{1}{d_T(m,p)}.
\]
Candidate membership hyperedges use normalized RRF scores. Within each local hypergraph, incident hyperedge weights are normalized so the total incident weight at each node sums to one.

Hypergraph diffusion propagates scores from the query through the local knowledge structure. Let $\mathbf{H} \in \{0,1\}^{|V_q| \times |\mathcal{E}_q|}$ be the vertex-hyperedge incidence matrix of $H_q$, $\mathbf{W}$ the diagonal hyperedge weight matrix, and $\mathbf{D}_v$, $\mathbf{D}_e$ the diagonal node-degree and hyperedge-degree matrices. The seed distribution $\mathbf{x}^{(0)}$ distributes mass uniformly over the question node, question entity nodes, and question MeSH nodes. Scores propagate through weighted hyperedges:

\[
  \mathbf{x}^{(t+1)} = (1-\alpha)\mathbf{x}^{(0)} + \alpha \cdot \mathbf{D}_v^{-1/2} \mathbf{H} \mathbf{W} \mathbf{D}_e^{-1} \mathbf{H}^\top \mathbf{D}_v^{-1/2} \mathbf{x}^{(t)},
\]

with $\alpha=0.85$ and $T=3$ iterations. The operator runs in three phases: hyperedge aggregation ($\mathbf{H}^\top \mathbf{D}_v^{-1/2} \mathbf{x}^{(t)}$), weight scaling ($\mathbf{W} \mathbf{D}_e^{-1}$), and node redistribution ($\mathbf{D}_v^{-1/2} \mathbf{H}$). Passage-level diffusion scores undergo min-max normalization within each question candidate set. We also compute weighted degree centrality, local node and hyperedge counts, shared-entity edge counts, document-MeSH edge counts, and hierarchy-edge counts as additional structural features.

We construct three architectural variants from the same candidate pool for controlled ablation. The pairwise graph variant decomposes multi-node hyperedges into anchor-based pairwise edges. The no-medical-knowledge hypergraph strips out all MeSH, entity, and PrimeKG annotations but keeps rank-band and candidate structure edges. The flat knowledge variant uses retrieval, biomedical semantic, MeSH, entity, and relation features without any graph construction.

\begin{algorithm}[H]
\SetAlgoLined
\caption{KCH-MedRank Knowledge-Constrained Evidence Reranking}
\label{alg:kch-medrank}
\KwIn{Question $q$, corpus $C$, biomedical knowledge $K$, source weights $\{w_s\}$}
\KwOut{Ranked evidence list $E$}
Retrieve top-$M$ passages from BM25, dense, fielded BM25, and MedCPT dual-encoder\;
Fuse candidate pool $D_q$ with weighted RRF: $\mathrm{RRF}(q,d) = \sum_s w_s/(k+r_s(q,d))$\;
\BlankLine
\If{graph or hypergraph variant}{
  Build local hypergraph $H_q = (V_q, \mathcal{E}_q)$ from $q$, $D_q$, documents, entities, MeSH concepts, and relation endpoints\;
  Add hyperedges for query-concept, passage-concept, document-MeSH, shared-concept clusters, hierarchy links, and PrimeKG relations\;
  \ForEach{hyperedge $e \in \mathcal{E}_q$}{
    Assign weight $w_e$ by evidence strength (entity/MeSH: normalized overlap; hierarchy: $1/d_T$; candidate: normalized RRF)\;
  }
  Normalize incident edge weights per node\;
  \BlankLine
  Initialize seed $\mathbf{x}^{(0)}$ on question, query-entity, and query-MeSH nodes\;
  \For{$t = 1$ \KwTo $T$}{
    $\mathbf{x}^{(t)} = (1-\alpha)\mathbf{x}^{(0)} + \alpha \cdot \mathbf{D}_v^{-1/2} \mathbf{H} \mathbf{W} \mathbf{D}_e^{-1} \mathbf{H}^\top \mathbf{D}_v^{-1/2} \mathbf{x}^{(t-1)}$\;
  }
  Normalize passage diffusion scores within $D_q$ (min-max)\;
  Compute centrality, local counts, and structural features $\phi_{\text{diff}}, \phi_{\text{cent}}, \phi_{\text{graph}}$\;
}
\BlankLine
\ForEach{passage $d \in D_q$}{
  Extract entity features $\phi_{\text{ent}}$ (Jaccard, coverage)\;
  Extract MeSH exact features $\phi_{\text{mesh}}$ (Jaccard, coverage)\;
  Extract MeSH hierarchy features $\phi_{\text{tree-sim}}, \phi_{\text{anc-match}}$\;
  Extract PrimeKG relation features $\phi_{\text{rel}}$ (count, coverage)\;
  Concatenate $\boldsymbol{\phi}(q,d)$ from retrieval, biomedical, and structural feature groups\;
}
\BlankLine
Train LambdaMART ranker on training set with query-group partitioning\;
Select $\beta$ on validation MRR@10: $s(q,d) = (1-\beta)f(q,d) + \beta \cdot s_{\text{RRF}}(q,d)$\;
Retrain on train+validation; score and sort $D_q$ once on held-out test split\;
\Return $E$ = passages of $D_q$ sorted by descending $s(q,d)$\;
\end{algorithm}

\subsubsection{Learning-to-Rank with LambdaMART}

The supervised reranker is a query-group LambdaMART model trained with LightGBM~\citep{ke2017lightgbm}. Each question defines one ranking group. The feature vector $\boldsymbol{\phi}(q,d)$ concatenates all feature groups:

\[
  \boldsymbol{\phi}(q,d) = [\mathrm{score}_{\text{BM25}}, \mathrm{score}_{\text{dense}}, \mathrm{score}_{\text{fielded}}, \mathrm{score}_{\text{CPT}}, \phi_{\text{cpt}}, \phi_{\text{ent}}, \phi_{\text{norm}}, \phi_{\text{mesh}}, \phi_{\text{rel}}, \phi_{\text{diff}},\phi_{\text{cent}},\phi_{\text{graph}}],
\]

where $\phi_{\text{cpt}}$ is the precomputed biomedical semantic score, $\phi_{\text{ent}},\phi_{\text{norm}},\phi_{\text{mesh}},\phi_{\text{rel}}$ are the biomedical knowledge features (including synonym-aware normalized variants $\phi_{\text{norm}}$), and $\phi_{\text{diff}},\phi_{\text{cent}},\phi_{\text{graph}}$ are the optional structural features.

LambdaMART minimizes a pairwise ranking loss with boosted regression trees. For a pair of passages $(d_i,d_j)$ with relevance labels $y_i > y_j$, the gradient contribution is:

\[
  \lambda_{ij} = \frac{-\sigma\big(f(q,d_j)-f(q,d_i)\big)}{1 + \exp\big(\sigma(f(q,d_i)-f(q,d_j))\big)} \cdot |\Delta\mathrm{NDCG}_{ij}|,
\]

where $\sigma(\cdot)$ is the logistic function and $\Delta\mathrm{NDCG}_{ij}$ is the change in NDCG@$k$ from swapping $d_i$ and $d_j$. Each tree fits the negative of the $\lambda$-weighted pseudo-residuals, so nodes that reduce large NDCG gaps draw stronger gradient signals.

After training, the final score blends the LambdaMART output with the original RRF rank for stability:

\[
  s(q,d) = (1-\beta) \cdot f(q,d) + \beta \cdot s_{\text{RRF}}(q,d),
\]

where $\beta \in \{0, 0.1, 0.2, 0.35\}$ is selected on validation MRR@10. We tune hyperparameters on the validation split over number of leaves $\{15,31\}$, learning rate $\{0.03,0.05\}$, number of estimators $\{80,160\}$, and blend weight $\beta$. The final model trains on the combined train-plus-validation set and evaluates exactly once on the held-out test split.
